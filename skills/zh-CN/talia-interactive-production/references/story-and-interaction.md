# 剧本与互动

使用 `story/node_graph.json` 作为创作结构的唯一真相。项目、角色、场景、节点、节拍、图片和选项都使用稳定 ID。供应商参数写入镜头工单，不写进戏剧结构。

每个节点应包含稳定 `id`、名称、类型、摘要、节拍、选项和 `auto_advance`。每个选项应包含玩家可见文本、目标节点、互动类型，以及可选的样式或 Tap Region 数据。

## 设计检查

- 分支前先明确玩家面对的戏剧问题。
- 选项代表意图、价值、风险或策略，不能只是不同措辞的“继续”。
- 选择前提供足够信息，让玩家明白自己在选择什么。
- 选择后尽快展示可见后果。
- 即使之后重新汇合，各分支也应有不同的情绪和因果结果。
- 结局要兑现选项作出的叙事承诺。
- 线性叙事放进自动推进节点；真正的决定使用明确选项。
- Tap Region 只能对应稳定、分离、清楚且足够大的画面目标。

Tap Region 使用 `0..1` 归一化坐标：`x`、`y`、`w`、`h`。热区必须跟随可见对象、彼此不重叠、避开字幕和 UI 安全区；对象含义不明确时提供可访问提示。结尾要保留稳定的互动停留时间。

不中断的动作、变身或揭示使用真实尾帧连续性；新地点、时间跳跃、蒙太奇节拍、分支后果或镜头语法变化使用切镜。
